# Action-driven workflow API contract

- Updated: 2026-09-28 EDT · Owner: workflow backend · State: implemented and database-tested.
- SQL argument names use `p_` prefixes. Errors use SQLSTATE `PT409` for stale revisions (HTTP 409), `42501` for forbidden access, `22023` for invalid transitions, `23505` for reused keys.
- `get_project_workflow(p_project_id uuid) -> jsonb`: `{project:{id,status,activity,workflowRevision,updatedAt,latestPublication:{id,number,decision,reviewRevision}|null},boards:[{id,name,activity,designerId,assignmentGeneration,workflowRevision,briefRevision,briefContent,currentRequest:{id,sequence,kind,outcome,roundId,content}|null,capabilities:{release,submit,requestChanges,close,reactivate}}],capabilities:{publish,review,deliver,respondFeedback}}`.
- Designers receive only their own boards/current generation and `latestPublication:null`; no `briefContent` or client decision. Clients receive `boards:[]`, no internal fields or board capabilities. Agency receives draft `briefContent` (fallback released) and its `briefRevision`.
- `save_production_brief(p_board_id uuid,p_content jsonb,p_expected_revision integer,p_publish boolean,p_request_id uuid,p_expected_board_revision integer default null,p_expected_assignment_generation integer default null) -> integer`; extra expected arguments are required when publishing. Draft saves retain the five-argument call.
- `send_board_round_for_request(p_board_id uuid,p_request_id uuid,p_expected_board_revision integer,p_note text,p_frame_url text,p_idempotency_key uuid) -> uuid`; open current request only.
- `handoff_board_work(p_project_id uuid,p_latest_publication_id uuid,p_expected_review_revision integer,p_board_decisions jsonb,p_request_id uuid) -> jsonb`; nullable publication/review for internal revisions. Decisions: `[{boardId,action:"continue"|"close",content?,expectedBoardRevision,expectedAssignmentGeneration,expectedBriefRevision}]`. At least one valid continue is required; omitted boards stay untouched.
- `share_workflow_version(p_project_id uuid,p_url text,p_note text,p_source_round_ids uuid[],p_expected_latest_publication_id uuid,p_expected_review_revision integer,p_confirm_replacement boolean,p_request_id uuid) -> uuid`; null latest/review for V1, exact latest guards thereafter. Sources may include submitted and historical retained rounds.
- `close_board_work(p_board_id uuid,p_expected_revision integer,p_request_id uuid) -> jsonb`; `reactivate_board_work(p_board_id uuid,p_expected_revision integer,p_request_id uuid) -> jsonb`. Reactivation requires a fresh release.
- `save_project_details_with_activity(p_project_id uuid,p_title text,p_description text,p_due_date date,p_start_date date,p_activity text,p_expected_updated_at timestamptz,p_expected_workflow_revision integer,p_request_id uuid) -> jsonb`; metadata/activity commit together.
- Authenticated callers cannot update project title, description, due date, or start date directly; use the guarded metadata RPC. Direct `board_position` updates remain granted.
- Removing a project assignment closes that designer's current board requests, clears drafts/releases, and increments board assignment generations. Reassignment requires a fresh release; historical rounds stay private to their original generation.
- Existing `review_publication(p_publication_id uuid,p_decision text,p_feedback text)` and `mark_project_delivered(p_project_id uuid)` remain, with current version/activity guards. Old `send_board_round` and `share_miro_version` lose authenticated execute access.
- First successful delivery stamps `projects.delivered_at`; an idempotent retry preserves its original value.
- New columns: `projects.activity,workflow_revision`; `design_boards.activity,assignment_generation,workflow_revision`; `publication_reviews.review_revision`; `design_versions.work_request_id,assignment_generation`.
- `action_notifications` derives agency prepare/review/respond/deliver and designer submit from current requests; backlog suppresses project work actions.
