# Trusted media service

This small HTTP service regenerates client-visible artwork from source bytes: project covers and final delivery files. It verifies the Supabase session before accepting a file, writes sanitized objects using a server-only service credential, and registers a SHA-256 attestation in the private backend schema. Browser clients cannot write to the covers or delivery buckets directly.

The legacy Versions feature (per-deliverable design uploads, video sanitisation and publication copies) has been retired; this service now only prepares project covers and delivery files. See `docs/superpowers/specs/2026-09-27-retire-versions-design.md`.

## Run locally

Install dependencies with `npm ci --prefix apps/media`. Copy `.env.example` to ignored `.env.local`, fill the values from the isolated local Supabase project, and run `npm --prefix apps/media start`. Poppler's `pdfinfo`/`pdftoppm` must be available on `PATH` — the process fails fast at startup if either is missing, rather than only on the first request that needs it. The default address is `http://127.0.0.1:55430`. `APP_ORIGIN` names the canonical browser origin, `http://localhost:3003` by default; `MEDIA_ALLOWED_ORIGINS` adds any further origins this machine serves the same application from, comma separated, which is what lets a `next dev` on its own port prepare a delivery or a cover. `local_stack.py` writes the local development origins for you.

Never put `SUPABASE_SERVICE_ROLE_KEY` in a browser environment variable. Both service and fixture credential files are ignored and should have file mode `0600`.

## API

- `GET /health` returns service readiness.
- `POST /deliveries/prepare?projectId=<project-uuid>` accepts a raw PNG, JPEG, WebP or PDF body, its exact `Content-Type`, and an optional URL-encoded `X-File-Name` display label. The project must be approved. It returns `{ "id", "storagePath", "mimeType", "fileSize" }` after persisting the trusted delivery record. Marking the project delivered is a separate idempotent agency action. New supplemental files after delivery are not supported.
- `POST /covers/prepare?projectId=<project-uuid>&visible=true|false` accepts a raw PNG, JPEG or WebP body and its exact `Content-Type`, agency only. It always re-encodes to PNG (`sanitizeCover`, which never falls back to JPEG the way `sanitizeRaster` does for a large opaque photo — the `project-covers` bucket accepts only `image/png`), saves it under `project-covers/<project-uuid>/<random-uuid>.png`, and calls the authenticated `set_project_cover` RPC with the caller's own token and `p_client_visible` from the `visible` query parameter (default `false`, since the RPC itself defaults to `false`). It returns `{ "path", "clientVisible" }`. If the RPC itself fails, the newly-saved object is deleted and the RPC's failure status is returned (`502` for a generic upstream failure). Once the RPC has *succeeded*, the database already points at the new object, so the request no longer fails on its account: the previous cover path it returns is discarded on a best-effort basis — a failure there is logged to stderr, not thrown, and never discards the new, now-live cover. An unsupported content type is `415`; a missing or unknown project is `404`.
- `POST /covers/clear?projectId=<project-uuid>` calls the authenticated `clear_project_cover` RPC with the caller's own token, agency only, deletes the returned storage path (if any), and returns `{ "cleared": true|false }`.

All POST routes require `Authorization: Bearer <Supabase-user-access-token>` and are agency only. Only a configured browser origin receives CORS permission: origins are compared whole against the allowlist, never reflected back because they asked, and an origin that is not named is refused with 403 before the body is read.

## Byte handling and limits

Raster images are decoded, orientation is applied, and fresh sRGB PNG pixels are encoded with Sharp's default metadata removal. PNG/JPEG/WebP source formats are accepted; multi-frame images, SVG and corrupt files are rejected.

PDFs are parsed and rendered by Poppler into fresh page images at 144 DPI, then rebuilt with pdf-lib. Page dimensions are preserved, including page rotation. Original metadata, scripts, attachments, links, forms, hidden text and author fields are never copied into the new document. This makes the output a flattened visual PDF; it does not preserve searchable text, forms or vector editability. Visible content is preserved, so agency review must still catch any creator identity visibly drawn into the artwork.

Limits are 50 MiB per raster input/output, 40 megapixels per raster, 20 PDF pages, 16 megapixels per rendered PDF page and 100 megapixels across a document. A cover's sanitized PNG output is still subject to this 50 MiB ceiling in the service itself, refusing rather than falling back to JPEG the way a delivery would; the `project-covers` bucket's own `file_size_limit` (10 MiB, `202609270001_project_covers.sql`) is a second, tighter ceiling enforced by Storage on the upload. Each Poppler child process has a 30-second timeout; the PDF loop has a 90-second deadline. Two jobs may run concurrently. Temporary files are private, randomly named and removed in `finally`. Failed preparation cleans up objects created during that request. Startup and hourly cleanup retry flagged deletions and remove up to 100 unreferenced preparations older than 24 hours. Cleanup failures produce a stable operator log message and retry on the next pass.

Scratch directories (`mkdtemp` under `tmpdir()`) are also swept once at boot, separately from the hourly attestation cleanup above: a normal request removes its own directory in a `finally`, but a crash mid-PDF-render can leave one behind, and — unlike the tmpfs `/tmp` this service used before the disk-backed scratch volume — a persistent volume does not clear that on container restart by itself. Every leftover `dawes-`-prefixed directory found at startup is removed before the server starts accepting requests; a fresh process has no in-flight request of its own, so anything already there is by construction an orphan from a previous run.

ZIP files are not accepted by this pipeline in any form; a delivery is limited to PNG, JPEG, WebP and PDF. Video is not accepted by this service at all: the legacy per-deliverable Versions feature that sanitised and published video has been retired (see `docs/superpowers/specs/2026-09-27-retire-versions-design.md`). No claim of sanitization is made for any format outside the ones named above.

## Tests and image

- `npm --prefix apps/media test` runs 31 tests across two files: `sanitize.test.js` (13) covers raster metadata stripping, invalid formats, pixel limits, PDF attachments/scripts, page preservation, and `sanitizeCover`'s unconditional PNG re-encode (including its refusal, rather than a JPEG fallback, of a photographic upload whose PNG output would exceed the byte limit); `server.test.js` (18) covers the allowed-origins allowlist, the scratch-directory sweep, `POST /covers/prepare`/`POST /covers/clear` (attestation bucket, the caller-token `visible` pass-through, previous-cover discard, a failed previous-cover discard that keeps the new cover, RPC-failure cleanup, 415/404) and the startup stale-asset sweep. These counts are a snapshot; the command's current output is authoritative.
- `npm --prefix apps/media run test:integration` requires the running local service and provisioned fixture credentials; it exercises real Auth, worker, Storage and SQL-attestation boundaries for delivery preparation, then removes its temporary objects.
- `docker build -t dawes-media:local apps/media` builds the production image with Poppler and production dependencies only. Inject environment variables at runtime, publish the chosen port, mount disk-backed scratch space and keep Supabase service access within the deployment's trusted network.
- `MEDIA_TEST_URL=http://127.0.0.1:55431 npm --prefix apps/media run test:integration` runs the same real pipeline checks against an isolated Docker image mapped to test port 55431.

The service returns stable error messages without exposing upstream response bodies, tokens or internal document metadata.
