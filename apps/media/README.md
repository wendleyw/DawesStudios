# Trusted media service

This small HTTP service regenerates client-visible artwork — and, for video, sanitises it at upload time — from source bytes. It verifies the Supabase session before reading source files, writes sanitized objects using a server-only service credential, and registers a SHA-256 attestation in the private backend schema. Browser clients cannot write to publication or delivery buckets directly, and (as of the video work) an internal video object is not eligible for publication until this service has attested it.

## Run locally

Install dependencies with `npm ci --prefix apps/media`. Copy `.env.example` to ignored `.env.local`, fill the values from the isolated local Supabase project, and run `npm --prefix apps/media start`. Poppler's `pdfinfo`/`pdftoppm` and `ffmpeg`/`ffprobe` must all be available on `PATH` — the process fails fast at startup if any of the four is missing, rather than only on the first request that needs it. The default address is `http://127.0.0.1:55430`. `APP_ORIGIN` names the canonical browser origin, `http://localhost:3003` by default; `MEDIA_ALLOWED_ORIGINS` adds any further origins this machine serves the same application from, comma separated, which is what lets a `next dev` on its own port prepare a publication. `local_stack.py` writes the local development origins for you.

Never put `SUPABASE_SERVICE_ROLE_KEY` in a browser environment variable. Both service and fixture credential files are ignored and should have file mode `0600`.

In any deployment where the container's root filesystem is read-only (`compose.yaml` runs this service that way), the video paths below need real disk-backed scratch space, not a RAM tmpfs: set `TMPDIR` to a writable, disk-backed mount sized for at least twice the video ceiling (`VIDEO_MAX_BYTES` in `apps/web/features/shared/upload-rules.ts`) plus headroom. `compose.yaml`'s `media-scratch` volume is the reference example; sizing a bigger tmpfs instead defeats the point, because a RAM-backed temp file is a Buffer in a costume.

## API

- `GET /health` returns service readiness.
- `POST /designs/sanitize-video` accepts JSON `{ "projectId", "rawPath", "mimeType" }` — `rawPath` is the `<project-uuid>/<uuid>.raw` object a resumable browser upload wrote to `internal-assets` — and returns `{ "path", "durationSeconds", "width", "height" }` after remuxing the file with `ffmpeg` (`-map_metadata -1 -c copy`, verified against its real container with `ffprobe`), uploading the clean copy under a fresh path, registering a sanitisation attestation for it, and deleting the raw object. This is the one POST route a designer assigned to the project — not only the agency — may reach: authorization mirrors `add_design`'s own `private.can_produce`, checked here against the named project once the caller's identity is established.
- `POST /publications/prepare` accepts JSON `{ "versionId": "<internal-version-uuid>" }` and returns `{ "assets": { "<internal-design-uuid>": "<project-uuid>/<random-uuid>.png-or-.mp4-or-.webm" } }`. An image is re-sanitized here, a second pass; a video is *copied* from the object `/designs/sanitize-video` already sanitised — copying it is refused if that object carries no sanitisation attestation, which is what stops a hand-uploaded, unsanitised video from reaching a client publication. Pass the map as `p_assets` and a stable per-submit UUID as `p_idempotency_key` to the authenticated `publish_version` RPC. Retry a lost response with the same key; use a new key for an intentional revision. Structured designs without uploaded files need no asset map entry. Source paths are resolved from authorized database rows, never supplied as external URLs.
- `POST /deliveries/prepare?projectId=<project-uuid>` accepts a raw PNG, JPEG, WebP or PDF body, its exact `Content-Type`, and an optional URL-encoded `X-File-Name` display label. The project must be approved. It returns `{ "id", "storagePath", "mimeType", "fileSize" }` after persisting the trusted delivery record. Marking the project delivered is a separate idempotent agency action. New supplemental files after delivery are not supported. Video is not a delivery format.
- `POST /assets/discard` accepts `{ "paths": ["<prepared-publication-path>"] }`, at most 20 paths, and returns `{ "discarded": [], "retained": [] }`. It removes only the caller's unreferenced prepared assets. If publication succeeded but its response was lost, referenced files are retained. The database flags files before deletion and removes the attestation only after Storage deletion succeeds.

All POST routes require `Authorization: Bearer <Supabase-user-access-token>`. Only a configured browser origin receives CORS permission: origins are compared whole against the allowlist, never reflected back because they asked, and an origin that is not named is refused with 403 before the body is read. Authentication always applies to non-browser requests; the *agency-only* role check applies to publication, delivery and asset-discard, but not to `/designs/sanitize-video`, which an assigned designer may also reach (see above).

## Byte handling and limits

Raster images are decoded, orientation is applied, and fresh sRGB PNG pixels are encoded with Sharp's default metadata removal. PNG/JPEG/WebP source formats are accepted; multi-frame images, SVG and corrupt files are rejected.

PDFs are parsed and rendered by Poppler into fresh page images at 144 DPI, then rebuilt with pdf-lib. Page dimensions are preserved, including page rotation. Original metadata, scripts, attachments, links, forms, hidden text and author fields are never copied into the new document. This makes the output a flattened visual PDF; it does not preserve searchable text, forms or vector editability. Visible content is preserved, so agency review must still catch any creator identity visibly drawn into the artwork.

Video (`video/mp4`, `video/webm`) is remuxed, not transcoded: `ffmpeg -map_metadata -1 -map_metadata:s -1 -map_chapters -1 -c copy` moves the existing streams into a fresh container, stripping container, per-stream and chapter metadata without decoding a frame, so it is bounded by disk/network time rather than CPU. `ffprobe` verifies the container really holds the codec its MIME type claims before any of this. Work happens through temp files on disk (`mkdtemp`), never a Buffer holding the whole file.

Limits are 50 MiB per raster input/output, 1 GiB per video, 40 megapixels per raster, 20 PDF pages, 16 megapixels per rendered PDF page and 100 megapixels across a document. Each Poppler child process has a 30-second timeout; the PDF loop has a 90-second deadline; a video probe has a 30-second timeout and a video remux has a 300-second timeout, each independently, because the probe only reads container headers off a file already on local disk while the remux moves the full stream data. Two jobs may run concurrently. Temporary files are private, randomly named and removed in `finally`. Failed preparation cleans up objects created during that request. Startup and hourly cleanup retry flagged deletions and remove up to 100 unreferenced preparations older than 24 hours; an internal video's sanitisation attestation is excluded from that sweep — it is a provenance record with no TTL, not a prepared/pending file. Published/delivery references are never selected. Cleanup failures produce a stable operator log message and retry on the next pass.

Scratch directories (`mkdtemp` under `tmpdir()`) are also swept once at boot, separately from the hourly attestation cleanup above: a normal request removes its own directory in a `finally`, but a SIGKILL or an OOM mid-remux can leave one behind, and — unlike the tmpfs `/tmp` this service used before the disk-backed scratch volume — a persistent volume does not clear that on container restart by itself. Every leftover `dawes-`-prefixed directory found at startup is removed before the server starts accepting requests; a fresh process has no in-flight request of its own, so anything already there is by construction an orphan from a previous run.

ZIP files are not accepted by this pipeline in any form; a delivery is still limited to PNG, JPEG, WebP and PDF. No claim of sanitization is made for any format outside the ones named above.

## Tests and image

- `npm --prefix apps/media test` runs 34 tests across two files: `sanitize.test.js` (13) covers raster metadata stripping, invalid formats, pixel limits, PDF attachments/scripts, page preservation and video remux/metadata-stripping/refusal behavior; `server.test.js` (21) covers the origin allowlist, `/designs/sanitize-video`'s authorization and path validation, `/publications/prepare`, and the boot-time scratch-directory sweep. These counts drift with the code; treat them as a snapshot, not a contract, if this file is ever out of date, trust `npm --prefix apps/media test`'s own output over this line.
- `npm --prefix apps/media run test:integration` requires the running local service and provisioned fixture credentials; it exercises real Auth, worker, Storage and SQL-attestation boundaries, then removes its temporary objects and restores the source design.
- `docker build -t dawes-media:local apps/media` builds the production image with Poppler, `ffmpeg`/`ffprobe` and production dependencies only. Inject environment variables at runtime, publish the chosen port, mount disk-backed scratch space (see "Run locally" above) and keep Supabase service access within the deployment's trusted network.
- `MEDIA_TEST_URL=http://127.0.0.1:55431 npm --prefix apps/media run test:integration` runs the same real pipeline checks against an isolated Docker image mapped to test port 55431.

The service returns stable error messages without exposing upstream response bodies, tokens or internal document metadata.
